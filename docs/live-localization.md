# 首次运行直接加载汉化

零协归档在启动前下载、完整校验并持久保存。游戏资源是否已经下载不再决定能否
启动汉化；日文配对索引保留为显示端后备，不再承担首次启动的前置门禁。

## 文本读取边界

- 游戏主进程在现有 IL2CPP 初始化完成边界安装文本读取接管。核对类、方法、
  静态/实例签名和相邻函数空间；只使用原有已登记的 hook 安装器。
- 接管 `TextAssetPatch.TextAssetPatchManager.LoadLocalizeFileSync(String)` 和
  `UnityEngine.TextAsset.get_text()`。日、英、韩资源表按目录和表名匹配到同一份译文。
  只有表名时须能唯一定位。资源表内按记录编号匹配，同一编号可以对应不同语言的原文。
- 全文后备索引对每张汉化资源分别读取日、英、韩对应原文，统一使用资源表、稳定编号、显示字段和嵌套结构配对。剧情、技能、饰品、事件、UI 和字符串数组共用相同规则。原文语言不改变模型身份。首次下载前按同一规则处理五张内置启动表。缓存指纹包含三种语言的源文件。
- 同文异译、数字、标点模板按资源身份及显示字段解析。英韩词典里的带空格名称以及方括号条件允许生成完整词组映射，仍使用包内译名、最长匹配和富文本保护规则。未配对的可识别条目以原文登记，防止套入别处译文。
- 原方法始终先执行；以其本次返回的本地化 JSON 作为结构基准，使用现有
  `TranslationJsonPairer` 的身份、字段、嵌套数组与重复记录规则，只替换已匹配的
  显示值。未翻译、损坏、未知或结构不匹配的值保留原文。返回内存中的 JSON，
  不改 APK、下载文件、资源清单或校验结果。
- 译文文件来自启动前校验的固定零协正式包；进程持有不可变清单快照，首次读取
  每个文件再核对哈希，按源内容摘要缓存结果并限制缓存总大小。没有文件轮询、
  后台重建循环或依赖宿主 Activity 返回的操作。
- 中文字体目录在启动前从同一包的明确显示字段生成。原生接管必须先确认中文
  字体可用，才向游戏返回汉化 JSON；工作线程不得创建 Unity 字体。
  字体和版式继续使用现有来源证明与组件恢复规则。
- 同一饰品内，重复的 abilityID 可以表示多种效果。重复编号不再整组丢弃：
  在相同父饰品与能力编号内，使用显示字段中的明确状态标记及数值组成完整指纹，
  仅在两侧均唯一且其余元数据一致时配对；重复的相同正文仍沿用原规则。
  无指纹、指纹冲突或缺少译文时保留原文，不按位置猜测，也不把能力编号跨饰品使用。
  配对版本随策略递增，使旧索引重新生成；实时合并结果只在本次游戏进程缓存，
  更新后直接使用新配对规则，已核验的零协下载包继续复用。

## 首次启动与更新

显示模型还通过共用 `JsonDataList<T>` 的取词边界处理，先于短 getter 和富文本加工。
按本地化模型类型、稳定 ID 和显示字段选择同一份零协译文，不由页面名称或此前出现的
文字决定。启动前从已校验正式包生成 LZFC2 字体目录及模型索引；schema 4 自动替换
旧目录，资源 ZIP 仍可复用。共享泛型函数必须核对闭合类型和实例调用约定，重复键
冲突保留原文。完整边界见 [本地化模型与语言字体归属](localized-model-and-font-ownership.md)。

`TextDataSet.LoadLocal/LoadRemote(LOCALIZE_LANGUAGE)` 读取前，在 Unity 主线程尝试准备中文字体；通过类型、实例调用约定、枚举底层类型及函数间距校验后才接入。工作线程仅复用已准备好的字体。此前等首个 TMP 字符串出现才准备字体，可能已经错过整张本地化表的首次读取。饰品弹窗的 `GetEgoGiftTextData()` 在返回完整模型后补做同一显示字段处理，覆盖其只有 8 字节、不能安全接管的子属性 getter；不修改奖励、能力编号或游戏数值。

用户只需点一次启动。内置文本在读取时加载译文，游戏正常登录和下载资源；
新资源在同一个游戏进程第一次读取时应用对应译文。已有资源同样走此路径。
汉化归档校验失败且无可用缓存时在 BYBUS 报错，不以准备模式悄悄启动日文游戏。
旧版资源准备页不再自动出现。恢复原文时同时停用实时资源清单和配对索引。

## 依据与验证

启动语言表恢复限定在已知 `TextDataSet` 的登录 UI、错误提示表：两张表的条目数均为零、远程文本尚未加载，且当前不在语言加载或恢复过程中，才允许重试。检查在原取词之前执行，不依赖原方法返回空对象还是占位模型。通过现有单例读取游戏原语言，严格核验 JP/EN/KR 枚举和方法签名，再由 Unity 主线程调用游戏自己的 `LoadLocal`。同一数据集的同一语言至多尝试一次；自定义语言模式、未知语言、已有条目、其他表和工作线程都不处理。

方法查找将“是否查找父类”和“是否静态调用”分别核验：`CustomLocalizeManager.IsUsing()` 是无参数静态方法，`TextDataSet.LoadLocal` 与语言、列表访问器是实例方法。绑定不完整时记录缺失契约的布尔摘要；回归同时覆盖实际绑定规则和运行时空表恢复，不能仅手工将绑定设置为可用。

已核验的普通及参数化 UI 加载入口也执行同一空表检查，覆盖游戏内部直接取字典或内联 getter 的路径；仍只加载现有数据集，不创建新对象，不以替换占位字符串作为恢复。取词参数在可能触发 GC 的加载期间保留，重新加载替换表对象时使用新的表。

恢复后重新取得表并执行原取词方法，不能直接将 `Unknown` 替换成某句译文。加载异常、表仍为空或元数据不匹配时保持原结果，并只记录阶段和计数；不删除资源、修改账号、改写语言选项或替代登录结果。空表恢复属于有限补救，不能据此宣称所有 Unknown 或登录失败具有同一个原因，需单独核对实际游戏结果。

当前官方 Android 构建的元数据包含上述同步读取接口和异步下载接口。商业产品
的宣传只说明使用体验，不能证明其内部实现；本方案依据本地实际游戏元数据及
结构化文本配对代码。验证覆盖无原文缓存、首次读取、读取后新增资源、重复身份、
缺失译文、元数据保持、损坏缓存和线程边界。云端运行观察另记实际结果，不以
单测代替游戏画面验证。
## 重复条目的消歧

零协资源中存在同一编号的多条显示记录。重复剧情编号可以继续通过说话者、语音及显示字段的结构唯一对应；显示字段的正文不能当作跨语言身份。重复饰品能力先按已有的状态标记和数值唯一对应，只有两边同组数量、元数据和显示字段结构完全一致，且已确认其他所有成员时，才配对最后一对剩余成员。不得将两条仍有歧义的效果按位置猜配。

发布包自身的模型目录遍历所有显示记录，由模型键冲突检查保留唯一译文；不能把跨语言消歧失败误用为丢弃包内模型记录的理由。配对规则变化同时更新后备索引、运行时模型目录和覆盖报告的缓存版本。
