# 首次运行直接加载汉化

零协归档在启动前下载、完整校验并持久保存。游戏资源是否已经下载不再决定能否
启动汉化；日文配对索引保留为显示端后备，不再承担首次启动的前置门禁。

## 文本读取边界

- 游戏主进程在现有 IL2CPP 初始化完成边界安装文本读取接管。核对类、方法、
  静态/实例签名和相邻函数空间；只使用原有已登记的 hook 安装器。
- 接管 `TextAssetPatch.TextAssetPatchManager.LoadLocalizeFileSync(String)` 和
  `UnityEngine.TextAsset.get_text()`。后者通过 Unity 对象名称匹配唯一的 `JP_` 资源，
  同名歧义拒绝。资源清单、其他语言、游戏数值和未知资源不处理。
- 原方法始终先执行；以其本次返回的日文 JSON 作为结构基准，使用现有
  `TranslationJsonPairer` 的身份、字段、嵌套数组与重复记录规则，只替换已匹配的
  显示值。未翻译、损坏、未知或结构不匹配的值保留原文。返回内存中的 JSON，
  不改 APK、下载文件、资源清单或校验结果。
- 译文文件来自启动前校验的固定零协正式包；进程持有不可变清单快照，首次读取
  每个文件再核对哈希，按源内容摘要缓存结果并限制缓存总大小。没有文件轮询、
  后台重建循环或依赖宿主 Activity 返回的操作。
- 中文字体目录在启动前从同一包的明确显示字段生成。原生接管必须先确认中文
  字体可用，才向游戏返回汉化 JSON；工作线程不得创建 Unity 字体。
  字体和版式继续使用现有来源证明与组件恢复规则。

## 首次启动与更新

用户只需点一次启动。内置文本在读取时加载译文，游戏正常登录和下载资源；
新资源在同一个游戏进程第一次读取时应用对应译文。已有资源同样走此路径。
汉化归档校验失败且无可用缓存时在 BYBUS 报错，不以准备模式悄悄启动日文游戏。
旧版资源准备页不再自动出现。恢复原文时同时停用实时资源清单和配对索引。

## 依据与验证

当前官方 Android 构建的元数据包含上述同步读取接口和异步下载接口。商业产品
的宣传只说明使用体验，不能证明其内部实现；本方案依据本地实际游戏元数据及
结构化文本配对代码。验证覆盖无原文缓存、首次读取、读取后新增资源、重复身份、
缺失译文、元数据保持、损坏缓存和线程边界。云端运行观察另记实际结果，不以
单测代替游戏画面验证。
