# 多渠道更新与安装包占用（2026-09-29）

用户选择优先稳定和节省空间：保留系统安装的游戏 APK，继续使用 BYBUS 容器里已有的账号和大资源。此次不切换独立容器安装模式，不卸载原版，不清除任一游戏数据。安装渠道不能作为游戏真实性或兼容性的证明。

## 安装与更新边界

- 本机游戏始终按固定包名读取 PackageManager 的版本、安装源和 APK 集合。真实来源单独展示；无法识别时显示未知/系统安装，不能写死 Google Play。
- Google Play 与 Uptodown 为可独立查询的版本渠道，各自校验游戏身份、保存版本和检查时间。网页查询失败保留该渠道旧记录并标为未刷新，不能把另一渠道结果冒充本渠道，也不能用最大版本值声称所有设备均可更新。
- 原安装商店、已验证的固定游戏页面和本地安装包分别作为更新入口。APKPure 当前页面直接请求返回 403，仅提供明确的网页入口，不假装存在可用的实时查询接口。网络信息不阻塞启动工作队列。
- “本机版本”“渠道可见版本”“容器已同步”“当前构建兼容性”是独立状态。发现新版本不等于新构建已被原生兼容配置支持。
- 本地更新通过系统 PackageInstaller 完整安装会话执行，保留系统和容器数据。支持完整 APK / APK 分包集合以及包含该集合的 XAPK/APKS ZIP 容器；只处理 APK，不运行归档里的代码或脚本。校验包名、版本、官方签名、分包一致性、需要的资源/原生库和本机兼容性，再显示可审阅的安装结果，由系统完成最终签名与原子安装校验。
- 降级、不完整集合、混合版本、未知签名或未通过兼容检查的构建应在替换系统游戏之前拒绝。
  内部版本 39 起，相同已验证原生结构可从当前官方 APK 自动解析布局，不再要求新版本号
  预先登记；启动与安装预检共用 [同结构判定](automatic-native-compatibility.md)。
  取消安装或进程重建不得删除已有游戏数据。导入目录、安装会话及 URI 权限须有明确生命周期，暂存文件不长期叠加。
- 游戏内部的商店跳转统一进入宿主的更新渠道页面，不再直接固定 Google Play。仅接受固定更新动作，不转发访客 Intent extras/selector/URI grants。

## 存储

现有运行模式依赖系统 APK，但不依赖原版下载的十多个 GB 资源。Android 普通应用不能直接清理另一应用私有目录；用户已下载的原版资源不会在本次升级时自动删除。

导入快照保持事务和回退信息，同内容 APK 可在宿主私有目录中通过硬链接复用；建立失败退回安全复制。不得链接游戏可写资源、跨应用文件或系统安装目录；不得让旧快照的清理删除当前快照内容。已有重复快照只在校验完整、无导入修复事务时去重。

导入重试先读取容器实际引用的 APK 路径。保留已提交的当前／上一代和容器仍引用的代，清理未引用的失败候选；引用查询失败则不执行清理。修复标记对应的候选只有在请求身份、完整 APK 集合和逐文件摘要均一致时才复用，否则重新准备。进程中断不得使每次重试叠加一份相同 APK，也不得删除仍在使用的文件。

## 更新页面交互（内部版本 20）

渠道使用固定顺序的分段选择器，Google Play 在前、Uptodown 在后；选择只改变高亮与渠道详情，不重排位置。选择色和详情用短渐变过渡，遵循系统动画设置。页面只保留一个独立的主跳转按钮，名称与目标地址都从当前选中渠道取得，查询失败也可手动前往商店。安装来源仍独立展示，不能随选择伪装成其他渠道；只有未被上述渠道覆盖的原安装商店保留次级入口。

版本信息、渠道选择与其他安装方式分组展示，移除夹在版本文字旁的“查看”按钮。刷新收进渠道标题行；本地文件更新、APKPure 网页采用同组次级操作。安装确认/待完成状态保留独立卡片，不改变安装会话处理。详情面板保持与关于页相同的高度约束，窄屏和较大字体允许内容换行并在面板内滚动。

本次只构建签名正式版并验证更新页布局、渠道切换与跳转。沿用已通过的更新/安装业务测试记录，不重跑全套测试、不启动游戏；本次结果与下面内部版本 19 的历史记录分开记录。
