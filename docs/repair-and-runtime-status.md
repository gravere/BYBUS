# 应用内修复与运行状态

修复由启动协调器的单工作队列及现有操作锁执行，不能与启动、安装或迁移并发。
停止容器游戏后重新同步系统安装包，校验并恢复内置中文字体，再重新生成汉化清单、
字体目录和文本索引。优先使用完整校验的本地正式包；无有效缓存才获取零协正式发布。
重建走现有原子发布路径，不能预先清空有效索引。账号、PlayerPrefs、游戏下载资源、
Google 组件及账号设置不属于修复目标，不能删除；不自动启动游戏。

修复页显示这三个步骤及结果；失败保留具体原因并提供重试和诊断入口，不宣称修复
游戏服务器、源包漏译或未知兼容问题。修复不等同于清除数据。

运行记录只展示当前 launch.request 对应的上次启动回执：启动时间、汉化加载、中文
字体与明确失败原因。准备完成、游戏进程确认和实际读取汉化是不同状态；不能将
hooks_installed 当作已进入游戏或全场景覆盖。当前后台操作独立展示，不混入历史记录。

字体来源证明保留完整包内文本及有界模板的约束。换行标签和实际换行可归一用于
完整文本核对；从新流程返回的混合语言正式显示字段也属于已知资源，字体身份不应
由是否含假名或韩文决定。不改变原译文、数字、富文本样式或任意未知文本的字体。
包含 noparse 的正式字段只可按完整原始字符串核对，不剥离标签或授权其中的任意
片段。普通模板匹配仍拒绝新添加的 noparse/font/sprite 标签。

设置将应用更新与汉化资源分开：前者只负责 BYBUS 安装包，后者放在底部汉化设置。
旧“停用汉化”仅停用索引、下一次启动仍会重建，现合并到修复，不保留重复入口。
手动修复及汉化更新会停止游戏，执行前确认；导航和只读查询不加确认。
独立“同步游戏”也并入修复，正常更新的同步仍由启动流程自动完成。资源准备失败页
原有两个相同回调的重试按钮仅保留主按钮。旧数据迁移会替换同名数据，ZIP 导入会停止
容器进程，两者在执行前确认；游戏安装保留包信息核对和系统安装确认。

清除数据入口只清理容器游戏的 Assets 和四个 UnityCache/Shared 下载目录，通过
GameStorage 执行，不使用 Android 清除应用数据或卸载接口。确认文案明确需重新下载，
保留账号、PlayerPrefs、Google 组件、系统原版和已下载汉化包。先停止游戏并撤销旧索引，
再清除资源；下次启动重新校验并按实时汉化流程加载。操作与启动、修复、迁移共享锁。
清理前验证全部目录的固定用途和链接边界，遍历不跟随链接；失败可重试，不声称已完成。

正式发行只上传一份完整安装包 BYBUS-Android.apk，保留旧客户端的固定名称；本地带
版本号产物用于归档与校验，不再重复上传。BYBUS.apk 仍是旧包名迁移衔接文件，单独标明用途。
