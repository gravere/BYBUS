# 中文文字的字体与材质同步

文字已经命中译文，并不代表最终字形和材质仍然正确。字体资格、主字体、材质、图集和排版必须沿实际刷新入口一起检查。

## 来源与富文本

- 使用完整正式译文、受限格式模板和组件内的已知段落证明来源，不能凭含汉字切换所有文本。
- 游戏追加的 `◆` 列表符号与已有 `•` 列表使用相同的完整条目核对：符号后的整句必须命中正式译文或参数受限的正式模板，每条均通过才切换字体。不能只凭“脑啡肽模块”等局部词语授权其余正文。
- 采光名称还会追加 ` - 5` 一类关卡编号，再与跳过战斗的确认句拼接。仅允许完整已知名称/模板后紧跟 ` - ` 和 1–6 位十进制编号；多行内容须逐行全部核对。组合结果不得进入原子词条缓存或再次作为名称拼接，不改变译文、编号或原有换行。
- 字体目录按正式包的显示字段提取全文，不借用日中配对器的身份消歧规则。重复 ID 或能力编号会使翻译配对保持原文，但不会让正式包中这些中文句子失去字体资格；字体目录本身不授予翻译映射。目录策略变化时必须使旧缓存失效。
- TMP 标签名称不区分大小写，合法的十六进制颜色简写与普通颜色标签都只改变装饰。字体证明应识别这些等价写法，但不改写传入游戏的标签、颜色或正文。
- `noparse` 内部是字面正文，必须原样比较；只允许忽略该区域外部的装饰标签。未知字体、图片、样式宏和额外正文不能凭剥除标签获得身份。
- 游戏的 Ruby 注音组件先测量正文，再把 `<ruby>` 转为定位、字号与偏移标签。仅对三个明确组件的实例 `ReplaceRubyTags(System.String) -> System.String` 核对签名和函数边界，在其测量前准备字体，并沿同一次调用传递完整译文来源。保留游戏的注音和自动排版，不把生成片段登记为通用词条。

## 材质与状态切换

- 切到中文主字体时，以 TMP 材质管理器转换游戏当前材质，保留颜色、描边、阴影及关键字，替换中文图集和对应指标。
- 已使用中文字体的组件仍需在文字准备/解析时核对材质。游戏可能原地修改材质，或者通过材质数组、内部方法重设材质，单独拦截两个材质 setter 不够。
- 转换材质保留其源材质的托管引用。刷新时回到该来源检查变化，不把转换结果再次当作日文材质；按实例重新计算材质留边，避免新的描边和阴影被旧网格边界截断。
- 中文图集上的局部材质实例可继续承载游戏的样式修改，但不能覆盖组件保存的原字体材质，避免恢复原字体时绑定中文图集。
- 局部实例的图集已经与中文主字体一致时，直接保留该实例，不再交给后备材质管理器复制。游戏持有的实例必须就是最终绘制所用的实例，否则动画改变了阴影或发光，屏幕仍在使用上一份副本。归还旧的转换材质租约时，保留原字体的恢复材质。
- 不强制全局黑色描边，不改原来的透明度、粗体、禁用态或阴影方向。材质共享使用有引用计数的租约，组件退出后归还；不增加每帧扫描或后台轮询。

## 检查方式

回归必须经过生产 `prepare_tmp_text` 入口，并覆盖首次赋值、已汉化组件再次刷新、预设原地改变、绕过单材质 setter 的替换、中文材质实例和组件恢复。直接调用材质转换函数只验证了工具函数，无法证明刷新路径会调用它。

中文材质实例回归还须覆盖不重新解析文字时修改阴影，以及重复读取实例、解析、再次读取的流程。仅在下一次解析后检查材质参数，会把不应发生的复制误判为正确。阴影数值一致也不等于显示尺寸一致；采样点数、图集留边、SDF 比例及实际源材质需单独核对，未采集时不能推断阴影缩放已正确。

有限诊断在原有采样间隔内记录当前与原字体的采样点数、图集留边、实际字号、自动字号和阴影关键字，并对照原材质的阴影参数。新增读取只使用核对返回类型及参数后的 Unity 元数据方法；缺失方法记为未知，不影响文字路径。采光类别覆盖推荐等级、加成、消耗等同页标签，但类别本身不授予译文身份。

完整译文扫描还应包含游戏实际使用的富文本包装、格式参数、逐字/分段、字体字形覆盖及正式包中尚未翻译的内容。纯文本命中率、模拟材质结果和真实游戏画面是不同证据，必须分别记录。

## 中文图集与原材质的尺度

游戏 488 安装资源中的 `HigashiOme-Gothic-C-1` 和 `Corporate-Logo-Bold-ver2 SDF`
均使用 34 点采样、5 像素 padding，材质 GradientScale 为 6。中文图集沿用这组尺度，
继续使用零协 Sarasa Gothic SC Bold、4096² 多图集。此前 32 点采样、9 像素 padding
使同一阴影参数对应的字面相对距离增大；复制材质数值并不能保留其实际显示尺度。
不能只检查颜色、字重或材质引用相等，还须核对采样点数、GradientScale 和 TMP 的
ScaleRatio。保留游戏自己的描边/阴影颜色、开关和动态变化，不通过删阴影或统一黑边修补。
