# 返回正在运行的游戏

首页启动与返回现有会话分开处理。后台游戏仍有存活进程及系统任务时，按钮显示“返回游戏”，通过系统 AppTask.moveToFront 恢复同一任务，不执行停止进程、重建索引或同步安装。冷启动才走原有完整汉化校验流程；需要更新正在使用的汉化资源时，沿用显式更新操作。

只认可宿主拥有、ShadowActivity 承载、基础 Intent MIME 精确指向目标虚拟包的任务，并要求容器进程和实际系统进程仍存活、任务包含 Activity。恢复失败保留现有会话并报告失败，不偷偷改为杀进程冷启动；任务已不存在时才按冷启动处理。系统负责唤醒被冻结的 Activity，不直接向冻结的访客进程调用 Binder。

诊断记录当前任务与进程快照，以及游戏 Activity 的 resume/pause/stop/destroy 边界，只记录 PID、taskId、组件类型和布尔状态，不记录 Intent extras、文字、账号或游戏资源。旧运行回执中的 PID 不能证明当前仍存活。

回归覆盖已有任务、已退出进程、Google/宿主任务排除、移动失败和冷启动分流。云端用无账号的真实虚拟 Google Activity 检查后台→宿主→原任务的系统路径和 PID 连续性；它不等同于实机 Unity 游戏后台表现。
